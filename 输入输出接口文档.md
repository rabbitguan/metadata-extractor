# 元数据提取服务输入输出接口文档

## 1. 基本信息

- 服务地址：`http://127.0.0.1:4000`
- 远程示例地址：`http://8.130.186.178:21005`
- 请求格式：`application/json`
- 响应格式：`application/json`
- 主要接口：
  - `POST /register`：提交网页、URL、文本或上传 JSON/XML，提取元数据。
  - `POST /query`：提交 DOI/CSTR 标识符，解析后提取元数据。

### 通用请求头

后端通过请求头识别当前用户，用户 ID 不放在请求体里。

| Header | 必填 | 说明 |
| --- | --- | --- |
| `Content-Type: application/json` | POST 请求必填 | 声明请求体为 JSON。 |
| `X-User-Id` | 建议必传 | 当前登录用户唯一 ID。后端用它隔离 URL 历史缓存和查询记录。 |
| `X-User-Name` | 否 | 当前登录用户名。可传 URL 编码值，例如 `%E5%BC%A0%E4%B8%89`。 |
| `X-User-Email` | 否 | 当前登录用户邮箱。 |

说明：

- `/register` 的 URL 历史缓存会按 `X-User-Id` 保存和查询。
- `/history`、`/history/lookup` 只返回当前 `X-User-Id` 下的数据。
- 前端查询记录写入 `/history` 时，也按 `X-User-Id` 保存。
- 本地测试可用 ModHeader 或 cURL 手动添加这些请求头。
- 不传 `X-User-Id` 时，后端会把用户 ID 当作空字符串，仅适合本地临时调试。

请求头示例：

```http
Content-Type: application/json
X-User-Id: 10086
X-User-Name: %E5%BC%A0%E4%B8%89
X-User-Email: zhangsan@example.com
```

## 2. 文本、网页、URL、上传文件元数据提取

### 接口地址

`POST /register`

### 标准请求头

```http
Content-Type: application/json
X-User-Id: {用户唯一ID}
X-User-Name: {URL编码后的用户名，可选}
X-User-Email: {用户邮箱，可选}
```

说明：

- `Content-Type`：必填，固定为 `application/json`。
- `X-User-Id`：建议必填，用于区分不同用户的历史缓存和查询记录。
- `X-User-Name`：可选，用户名建议 URL 编码后传入。
- `X-User-Email`：可选，用户邮箱。

### 标准请求体

```json
{
  "source": "url",
  "mode": "common",
  "strategy": "auto",
  "force_reanalyze": false,
  "dynamic_render": "auto",
  "llm_provider": "deepseek",
  "llm_api_key": "sk-...",
  "text": "待分析文本，source=text/web/upload 时使用",
  "html": "<html>页面 HTML，source=web 时可传</html>",
  "url": "https://example.org/resource",
  "title": "页面标题或上传文件名"
}
```

### 请求体字段说明

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `source` | string | 否 | 输入来源。可选值：`text`、`web`、`url`、`upload`。默认 `text`。 |
| `mode` | string | 否 | 提取模式。可选值：`common`、`domain`。默认 `common`。 |
| `strategy` | string | 否 | 提取策略。可选值：`auto`、`llm`、`rule`、`upload_rule`。默认 `auto`。 |
| `force_reanalyze` | boolean/string | 否 | 是否跳过历史缓存并重新分析。支持 `true`、`false`、`"1"`、`"true"`。默认 `false`。 |
| `dynamic_render` | string/boolean | 否 | URL 直抓动态渲染策略。支持 `auto`、`always`、`never`，也兼容 `true/false`、`1/0` 等写法。默认 `auto`。 |
| `llm_provider` | string | 否 | 大模型平台。支持 `siliconflow`、`openai`、`deepseek`、`dashscope`、`zhipu`，默认 `siliconflow`；也兼容 `deepseep`、`aliyun`、`qwen`、`glm` 等别名。 |
| `llm_api_key` | string | 否 | 大模型 API Key。系统先尝试内置规则，规则无法覆盖且需要调用大模型时才使用该 Key。不传时使用所选平台对应的环境变量默认 Key。也兼容字段名 `api_key`。 |
| `text` | string | 条件必填 | 待分析文本。当 `source=text/web/upload` 时需要提供。 |
| `html` | string | 否 | 页面 HTML，用于规则提取和历史记录保存。 |
| `url` | string | 条件必填 | 页面地址。当 `source=url` 时必填。 |
| `title` | string | 否 | 页面标题或上传文件名。文件名以 `.json` 或 `.xml` 结尾时会按结构化上传解析。 |

## 3. DOI/CSTR 标识符解析并提取元数据

### 接口地址

`POST /query`

### 标准请求头

```http
Content-Type: application/json
X-User-Id: {用户唯一ID}
X-User-Name: {URL编码后的用户名，可选}
X-User-Email: {用户邮箱，可选}
```

说明：

- `Content-Type`：必填，固定为 `application/json`。
- `X-User-Id`：建议必填，用于区分不同用户的查询记录。
- `X-User-Name`：可选，用户名建议 URL 编码后传入。
- `X-User-Email`：可选，用户邮箱。

### 标准请求体

```json
{
  "source": "identifier",
  "mode": "common",
  "llm_provider": "deepseek",
  "llm_api_key": "sk-...",
  "identifiers": "10.48550/arXiv.2303.14524 或 CSTR:17081.11.besiii.4180data.RunID47050",
  "text": "不传 identifiers 时，可从文本中自动提取 DOI/CSTR",
  "html": "<html>不传 identifiers 和 text 时，可从 HTML 中自动提取 DOI/CSTR</html>"
}
```

### 请求体字段说明

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `source` | string | 否 | 固定建议传 `identifier`。 |
| `mode` | string | 否 | 提取模式。可选值：`common`、`domain`。默认 `common`。 |
| `llm_provider` | string | 否 | 大模型平台。支持 `siliconflow`、`openai`、`deepseek`、`dashscope`、`zhipu`。解析出的资源页面规则无法覆盖时用于大模型兜底。 |
| `llm_api_key` | string | 否 | 大模型 API Key。仅在 DOI/CSTR 解析出的资源页面规则无法覆盖、需要大模型兜底时使用。不传时使用平台默认配置。 |
| `identifiers` | string/array | 条件必填 | DOI/CSTR 字符串或数组。 |
| `text` | string | 条件必填 | 不传 `identifiers` 时，可从文本中自动提取 DOI/CSTR。 |
| `html` | string | 条件必填 | 不传 `identifiers` 和 `text` 时，可从 HTML 中自动提取 DOI/CSTR。 |

说明：`identifiers` 优先级最高；未传时依次从 `text`、`html` 中提取 DOI/CSTR。解析标识符得到资源页面后，后端先走内置规则，规则无法覆盖时再按 `llm_provider` / `llm_api_key` 调用大模型兜底。

```json
}
```

请求头：

```http

```

```json

  "mode": "common",
  "identifiers": "10.48550/arXiv.2303.14524"
}
```

## 4. 输出字段结构说明

### 顶层结构

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `zh` | object | 中文元数据结果。 |
| `en` | object | 英文元数据结果。 |
| `items` | array | `/query` 接口返回的多标识符结果列表。 |

### 中文结果结构

| 路径 | 说明 |
| --- | --- |
| `zh.核心元数据` | 所有资源通用的核心元数据字段。 |
| `zh.数据集元数据` | 当资源被判定为数据集时返回。 |
| `zh.数据论文元数据` | 当资源被判定为数据论文时返回。 |
| `zh.其他元数据` | 当资源被判定为其他类型时返回。 |

### 英文结果结构

| 路径 | 说明 |
| --- | --- |
| `en.Core Metadata` | 所有资源通用的核心元数据字段。 |
| `en.Dataset Metadata` | 当资源被判定为数据集时返回。 |
| `en.Data Paper Metadata` | 当资源被判定为数据论文时返回。 |
| `en.Other Metadata` | 当资源被判定为其他类型时返回。 |

### 空值占位

后端会补齐必需字段。未提取到的字段使用以下占位值：

| 语言 | 占位值 |
| --- | --- |
| 中文 | `未提取到` |
| 英文 | `Not extracted` |

## 5. 调用示例

### 本地调用 `/register`

```bash
curl -X POST http://127.0.0.1:4000/register \
  -H "Content-Type: application/json" \
  -H "X-User-Id: 10086" \
  -d '{
    "source": "text",
    "mode": "common",
    "strategy": "auto",
    "text": "Title: Example Data Paper. DOI: 10.1234/example."
  }'
```

### 远程调用 `/register`

```bash
curl -X POST http://8.130.186.178:21005/register \
  -H "Content-Type: application/json" \
  -H "X-User-Id: 10086" \
  -d '{
    "source": "url",
    "url": "https://arxiv.org/abs/2303.14524",
    "mode": "common",
    "strategy": "auto"
  }'
```

### 本地调用 `/query`

```bash
curl -X POST http://127.0.0.1:4000/query \
  -H "Content-Type: application/json" \
  -H "X-User-Id: 10086" \
  -d '{
    "source": "identifier",
    "mode": "common",
    "identifiers": "10.48550/arXiv.2303.14524"
  }'
```
